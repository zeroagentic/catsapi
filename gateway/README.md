# CatsApi Gateway

OpenAI-compatible LLM gateway gated by CatsApi NFT ownership on BNB Smart Chain.

**Live:** https://api.prjktspace.web.id — permanent Cloudflare Tunnel
endpoint on the project's own domain (named tunnel `catsapi-gateway`,
DNS on Cloudflare; the operator host also records it in
`~/workspace/catsapi-gateway/hosting/current-url.txt`).
the project website's gateway section.

## How it works

1. **Prove ownership (no transaction).** The holder signs a plain-text message
   (`CatsApi Gateway key request` + address + timestamp) with their wallet.
2. **On-chain verification.** The gateway recovers the signer, then reads the
   CatsApi contract on BSC: `balanceOf` + an `ownerOf` scan. No NFT → `403`.
3. **Key issuance.** A `sk-cats-…` API key is issued. Only its SHA-256 hash is
   stored server-side; the key itself is shown once. Re-issuing rotates
   (revokes) the previous key.
4. **Quota by tier.** Monthly quota = sum over owned tokens of the tier quota
   (Common 500K · Rare 1M · Epic 5M · Legendary 20M · Mythic 50M tokens).
   The token→tier assignment is the project's provenance-committed map
   (SHA-256 in the main README); it stays server-side until the collection reveal.
5. **Metering.** `POST /v1/chat/completions` checks the key's month-to-date
   usage first (`402` when exhausted), forwards to the upstream LLM, and
   records the upstream-reported `usage.total_tokens` against the key.
   A global monthly cap protects the operator's upstream account.
6. **Upstream.** Any OpenAI-compatible provider. The production instance fronts
   an upstream that only serves the Responses API, so the gateway translates
   chat/completions ⇄ responses transparently (`UPSTREAM_API_STYLE=responses`).

## API

| Endpoint | Auth | What |
| --- | --- | --- |
| `GET /` | — | Landing + instructions |
| `GET /health` | — | Status, contract, models, global usage |
| `POST /v1/keys` | wallet signature | `{address, message, signature}` → `{api_key, quota_per_month, tokens[]}` |
| `GET /v1/me` | Bearer key | Quota, usage and remaining for this month |
| `GET /v1/models` | Bearer key | Model list |
| `POST /v1/chat/completions` | Bearer key | OpenAI-compatible chat (non-streaming in the MVP) |

## Run your own

```bash
cd gateway
cp .env.example .env    # set upstream credentials
npm start               # node server.mjs, listens on 127.0.0.1:8787
```

You also need `config/tier-map.json` (tokenId → tier/quota) on the server —
generated by the collection's metadata pipeline, deliberately not in this repo
before reveal.

## Verified end-to-end (2026-11-19)

Local fixture (MockAgentId + the real contract on a local chain): key issuance
200 with the correct 500K Common quota, a live chat completion returned through
the translation layer, usage metered on `/v1/me`, and a wallet without an NFT
rejected with 403. The same negative-path test passes against the production
instance on BNB mainnet through the public URL.

## Owner dashboard

`GET /admin` on the gateway domain — a single-page dashboard for the contract
owner (and the operator's agent):

- **Login:** sign a message with the contract-owner wallet; the gateway checks
  the signer against the contract's `owner()` on-chain. Session = 24 h.
  The agent can use a localhost-only `AGENT_ADMIN_TOKEN` header instead.
- **Overview:** contract + owner, minted / free-minted counters, global usage
  vs the monthly cap, key counts, the current public tunnel URL.
- **Provider:** the single upstream (Xingchi) — base URL, API style, live
  `/models` probe (cached 60 s), model list.
- **Keys:** every issued key (wallet, tokens/tiers, quota, used/remaining,
  request count, last used, status) with a one-click **Revoke**.

Verified 2026-11-19: fixture test 10/10 (owner login, non-owner 403, overview
auth, revoke kills the key) and the same checks pass on the production
instance through its public URL.

## Client setup (no User-Agent tricks)

End users never talk to the upstream directly, so the upstream's User-Agent
requirement is absorbed by the gateway: it injects the required UA on every
upstream call, and it performs **no UA check on inbound requests**. Any
OpenAI-compatible client works with just two settings — Base URL (gateway +
`/v1`) and the `sk-cats-` key. Verified end-to-end 2026-11-19 with a default
client UA and with `python-requests/2.31.0`: both returned HTTP 200 through
the real upstream.
